\# Feature Focus



\## Purpose



Direct the viewer from a complete product interface toward one specific

feature, demonstrate its behavior, communicate its value and return the

viewer to the larger product context when necessary.



Feature Focus is not:



ZOOM INTO BUTTON

→ CLICK

→ ZOOM OUT



Feature Focus is:



CONTEXT

→ ATTENTION

→ ISOLATION

→ ACTION

→ CONSEQUENCE

→ RESULT

→ PRODUCT VALUE



The feature must become easier to understand,

not merely larger on screen.



\---



\# 1. When to Use



Use Feature Focus for:



\- SaaS feature demonstrations

\- application product videos

\- AI feature reveals

\- dashboard walkthroughs

\- product launch films

\- automation demonstrations

\- mobile app features

\- analytics features

\- CRM workflows

\- finance applications

\- health and fitness apps

\- feature comparison

\- before/after sequences



\---



\# 2. Core Narrative



A strong feature sequence answers:



WHERE IS IT?



WHAT IS IT?



WHAT DOES THE USER DO?



WHAT DOES THE PRODUCT DO?



WHAT CHANGES?



WHY DOES THAT MATTER?



\---



\# 3. Default Feature Arc



Use:



PRODUCT CONTEXT



→ FEATURE IDENTIFICATION



→ FEATURE ISOLATION



→ INTERACTION



→ SYSTEM RESPONSE



→ RESULT



→ VALUE



→ NEXT SHOT



Not every feature requires every stage,

but the logic should remain clear.



\---



\# 4. Context



Show enough of the product to establish location.



Context may include:



\- dashboard

\- navigation

\- surrounding cards

\- device

\- workflow

\- page

\- system



Do not begin from an isolated feature if the viewer needs product context.



\---



\# 5. Feature Identification



Direct attention before major movement.



Possible:



\- contrast

\- highlight

\- cursor

\- local glow

\- surrounding dim

\- small scale emphasis

\- camera preparation

\- label



The viewer should know what will become important.



\---



\# 6. Feature Isolation



Reduce competition around the hero feature.



Possible:



SURROUNDING DIM



DEPTH SEPARATION



SCALE EMPHASIS



FOCUS PULL



CAMERA PUSH



CROP



CARD EXPANSION



BACKGROUND BLUR



Use the smallest mechanism necessary.



\---



\# 7. Isolation by Contrast



Keep geometry unchanged.



Reduce surrounding:



\- luminance

\- saturation

\- opacity

\- motion



Useful for enterprise SaaS.



Very clean.



\---



\# 8. Isolation by Depth



Hero moves forward while context moves backward.



Useful for:



\- premium product film

\- cinematic UI

\- complex dashboards



Maintain recognizable product structure.



\---



\# 9. Isolation by Scale



Hero becomes larger.



Useful when feature is physically small.



Avoid aggressive scale jumps.



\---



\# 10. Isolation by Camera



Camera approaches the feature.



Useful for:



OVERVIEW

→ DETAIL



Camera should land before dense interaction begins.



\---



\# 11. Isolation by Expansion



Feature expands into a larger state.



Useful for:



\- cards

\- panels

\- analytics

\- AI results

\- media



Prefer shared-element continuity.



\---



\# 12. Isolation by Crop



Reframe composition around feature.



Useful when product remains flat.



Often cleaner than unnecessary 3D.



\---



\# 13. Feature Hero



Once isolated,

the feature becomes the visual hero.



Hero should have:



\- sufficient scale

\- stable orientation

\- readable content

\- clear action point

\- enough negative space



\---



\# 14. Interaction



Show the minimum interaction required to explain the feature.



Possible:



CLICK



TYPE



DRAG



SCROLL



SELECT



TOGGLE



DROP



DRAW



VOICE



GESTURE



Avoid unnecessary user actions.



\---



\# 15. Interaction Trigger



Every product response needs a clear trigger.



Pattern:



USER ACTION

→ PRODUCT RESPONSE



or:



SYSTEM EVENT

→ PRODUCT RESPONSE



Do not animate results without establishing causality when causality matters.



\---



\# 16. Cursor as Trigger



Useful for desktop software.



Pattern:



CURSOR APPROACHES

→ TARGET RESPONDS

→ CLICK

→ PRODUCT ACTION



Cursor should not wander.



\---



\# 17. Touch as Trigger



Useful for mobile.



Possible:



TAP



SWIPE



DRAG



PINCH



LONG PRESS



Keep touch representation subtle.



\---



\# 18. Keyboard as Trigger



Useful for:



\- search

\- command palettes

\- prompts

\- forms

\- coding

\- AI interfaces



Typing speed should remain readable.



\---



\# 19. System Trigger



Not all features are user-triggered.



Possible:



LEAD ARRIVES



PAYMENT OCCURS



MESSAGE RECEIVED



WORKFLOW RUNS



AI FINISHES



DATA UPDATES



Visualize the event clearly.



\---



\# 20. System Response



After trigger,

show what product does.



Possible:



STATE CHANGE



DATA FLOW



ANIMATION



RESULT CARD



NOTIFICATION



CHART UPDATE



WORKFLOW EXECUTION



AI RESPONSE



The response is usually more important than the click.



\---



\# 21. Cause and Effect



Preserve order:



CAUSE

→ PROCESS

→ EFFECT



Do not reveal result before viewer understands trigger unless deliberate

foreshadowing is being used.



\---



\# 22. Result



The result should receive its own visual emphasis.



Possible:



\- hold

\- contrast

\- metric

\- highlight

\- camera settle

\- sound accent



Do not immediately leave after result appears.



\---



\# 23. Value



Feature demonstration should communicate more than operation.



OPERATION:

what happened?



VALUE:

why should the viewer care?



Example:



OPERATION:

AI scores the lead.



VALUE:

sales team knows who to contact first.



Visual storytelling should support both.



\---



\# 24. Feature Focus Types



Use:



MICRO FEATURE



STANDARD FEATURE



HERO FEATURE



SYSTEM FEATURE



TRANSFORMATION FEATURE



PROOF FEATURE



\---



\# 25. Micro Feature



Small behavior.



Examples:



\- filter

\- toggle

\- quick action

\- notification



Duration should be short.



Do not over-direct minor functionality.



\---



\# 26. Standard Feature



One meaningful product capability.



Example:



dashboard filter

→ updated analytics



Use complete:



context

→ action

→ result.



\---



\# 27. Hero Feature



Central selling point.



May receive:



\- stronger camera

\- more depth

\- signature effect

\- stronger sound

\- more screen time



Reserve richer treatment for hero features.



\---



\# 28. System Feature



Feature spans multiple product areas.



Example:



lead capture

→ AI qualification

→ CRM

→ automation



Use data flow or spatial continuity.



\---



\# 29. Transformation Feature



Shows before → after.



Examples:



RAW DATA

→ INSIGHT



MANUAL

→ AUTOMATED



PROMPT

→ OUTPUT



LEAD

→ QUALIFIED LEAD



Make transformation visually explicit.



\---



\# 30. Proof Feature



Demonstrates measurable outcome.



Examples:



+32% CONVERSION



12H SAVED



98% MATCH



2.4X FASTER



Only use supported/real metrics.



Do not fabricate proof.

\---



\# 34. Macro Focus



Zoom/reframe tightly around small UI detail.



Useful for:



\- toggle

\- icon

\- small metric

\- cursor interaction



Return context afterward if location matters.



\---



\# 35. Depth Focus



Hero separates spatially.



Useful for:



\- complex interface

\- feature ecosystem

\- premium launch



Avoid when simple crop solves the problem.



\---



\# 36. Interaction Focus



User action is central.



Useful for:



\- intuitive UX

\- drag/drop

\- command palette

\- builder

\- editor



Make action unmistakable.



\---



\# 37. Data Focus



Feature produces information.



Pattern:



ACTION

→ PROCESS

→ DATA UPDATE

→ INSIGHT



Useful for analytics.



\---



\# 38. AI Focus



Pattern:



INPUT

→ AI PROCESS

→ OUTPUT

→ VALUE



Do not represent AI processing with random particles alone.



Use visual metaphor tied to actual function.



\---



\# 39. Before / After Focus



Pattern:



BEFORE

→ ACTION

→ TRANSFORMATION

→ AFTER



Useful for communicating value quickly.



\---



\# 40. Composition



Feature should occupy intentional region.



Possible:



CENTER HERO



RULE-OF-THIRDS HERO



TEXT + FEATURE



FEATURE + RESULT



INPUT + OUTPUT



Choose according to story.



\---



\# 41. Text + Feature



Common SaaS composition:



LEFT

message



RIGHT

feature



or reverse.



Text should explain value,

not duplicate visible UI.



\---



\# 42. Input + Output



Useful for:



AI



automation



search



generation



analytics



Composition:



INPUT

→ PROCESS

→ OUTPUT



Spatial relationship should reinforce flow.



\---



\# 43. Feature + Result



Keep interaction and result visible simultaneously when useful.



Example:



FILTER

left



UPDATED CHART

right



Viewer immediately understands consequence.



\---



\# 44. Camera



Camera options:



STATIC



PUSH



PULL



LATERAL REFRAME



MACRO PUSH



FOLLOW



Choose according to information need.



\---



\# 45. Static Camera



Best when UI interaction itself provides enough motion.



Strong default for product truth.



\---



\# 46. Push



Use to isolate feature.



Sequence:



CONTEXT

→ PUSH

→ LAND

→ ACTION



\---



\# 47. Pull



Use after result to restore product context.



Sequence:



RESULT

→ HOLD

→ PULL

→ PRODUCT



\---



\# 48. Lateral Reframe



Useful when feature is off-center.



Camera shifts composition rather than simply zooming.



Can create space for explanatory typography.



\---



\# 49. Macro Push



For very small details.



Use sparingly.



Extreme macro can disconnect viewer from product.



\---



\# 50. Follow



Follow meaningful moving element.



Example:



LEAD

→ QUALIFICATION

→ CRM



Useful for multi-stage features.



\---



\# 51. Camera Landing



Never perform critical interaction while camera is still aggressively moving.



Prefer:



MOVE

→ SETTLE

→ INTERACT

→ RESULT



\---



\# 52. Motion



Primary motion should represent feature behavior.



Secondary motion may support:



\- hierarchy

\- depth

\- attention



Do not let cinematic motion overpower product action.



\---



\# 53. Feature Highlight



Possible:



border



fill



glow



shadow



scale



spotlight



underline



Use one dominant highlight mechanism.



\---



\# 54. Surrounding Dim



One of the strongest focus tools.



Pattern:



PRODUCT

→ SURROUNDING UI DIM

→ HERO REMAINS

→ ACTION



Simple and effective.



\---



\# 55. Feature Extraction



Feature physically leaves product plane.



Useful for:



\- hero feature

\- explanation

\- dimensional product film



Maintain visual link to original location.



\---



\# 56. Feature Reintegration



After demonstration,

feature returns to interface.



Useful for reminding viewer:



this capability belongs to the actual product.



\---



\# 57. Background Treatment



Possible:



UNCHANGED



DIM



BLUR



DEPTH



DESATURATE



DARKEN



Choose minimum necessary.



\---



\# 58. Blur



Use when depth/focus is meaningful.



Avoid heavy blur around dense UI because it can look artificially cinematic.



\---



\# 59. Lighting



Hero feature may receive local light.



Possible:



radial light



edge light



glow activation



environmental spill



Lighting should respond to feature state.



\---



\# 60. Sound



Useful layers:



FOCUS

subtle tonal shift



INTERACTION

click/tap



PROCESS

soft motion/data sound



RESULT

confirmation/accent



VALUE

music lift or hold



Do not sonify every micro-state.



\---



\# 61. Feature Focus + Voiceover



Coordinate visual beats with spoken structure.



Example:



"Automatically qualify every lead."



AUTOMATICALLY

→ trigger/process



QUALIFY

→ AI feature



EVERY LEAD

→ multiple results



Visual should support phrase meaning.



\---



\# 62. Feature Focus + Typography



Use typography for:



VALUE



CATEGORY



RESULT



Do not describe obvious button clicks.



Bad:



"Click the Analyze button."



Better:



"Know which leads deserve attention."



\---



\# 63. Timing



Conceptual:



CONTEXT

10–20%



FOCUS

10–15%



ACTION

10–20%



PROCESS

10–25%



RESULT

20–30%



HOLD / VALUE

15–25%



Adapt to feature complexity.



\---



\# 64. Context Duration



Show only enough context to establish location.



If product was established in previous shot,

context can be shorter.



\---



\# 65. Action Duration



User action should feel intentional,

not painfully slow.



Cursor travel should be efficient.



Typing should balance realism and pacing.



\---



\# 66. Result Duration



Result usually deserves more time than click.



The viewer cares about outcome.



\---



\# 67. Feature Sequence Chaining



Multiple feature focuses may form:



FEATURE A

→ RESULT

→ SHARED ELEMENT

→ FEATURE B

→ RESULT

→ FEATURE C



Avoid resetting to full dashboard after every feature unless context requires it.



\---

Pattern:



FEATURE

→ RESULT

→ RESULT



Useful for launch montage.



Keep each micro-story understandable.

\# 69. Feature Escalation

simple

\---



\# 86. Avoid — Zoom Equals Focus



Problem:



camera zooms but hierarchy does not change.



Fix:



combine camera with intentional isolation.



\---



\# 87. Avoid — Click Demo



Problem:



sequence only shows where cursor clicks.



Fix:



emphasize consequence and value.



\---



\# 88. Avoid — Tutorial Mode



Problem:



video becomes step-by-step training.



Fix:



show only interactions needed to communicate selling point.



\---



\# 89. Avoid — Fake Product Behavior



Do not invent product states that do not exist unless clearly conceptual.



Product film can enhance presentation,

but should not misrepresent functionality.



\---



\# 90. Avoid — No Context



Problem:



viewer sees a floating card but does not know where it belongs.



Fix:



establish or restore product context.



\---



\# 91. Avoid — No Result



Problem:



interaction occurs but outcome is not shown.



Fix:



make result a distinct visual beat.



\---



\# 92. Avoid — No Value



Problem:



viewer understands operation but not benefit.



Fix:



connect result to user/business outcome.



\---



\# 93. Avoid — Excessive Isolation



Problem:



surrounding product disappears completely.



Fix:



preserve enough context when product relationship matters.



\---



\# 94. Avoid — Simultaneous Events



Problem:



cursor, camera, chart, typography and background all move at once.



Fix:



sequence attention.



\---



\# 95. Avoid — Repeated Pattern



If every feature uses identical:



PUSH

→ CLICK

→ PULL



film becomes predictable.



Maintain grammar but vary shot structure.

\# 105. Implementation Routing



Use REMOTION when:



\- UI is code-based

\- interaction can be recreated programmatically

\- reusable product scenes are needed



Use AFTER EFFECTS when:



\- detailed art direction

\- complex compositing

\- manual interaction choreography

\- premium finishing



Use DAVINCI/FUSION when:



\- editing existing product captures

\- compositing rendered UI

\- final sequence and sound

\# 107. Review Checklist



\[ ] Product context is clear



\[ ] Feature is easy to locate



\[ ] Focus method supports hierarchy



\[ ] Interaction trigger is clear



\[ ] Product response follows trigger



\[ ] Result receives emphasis



\[ ] Viewer understands value



\[ ] Camera does not interfere with interaction

\[ ] Feature receives enough hold time



\[ ] Transition out follows result logically

\---



\# 108. Creative Director Rule



Do not say:



"Zoom into the AI button and click it."



Define:



CONTEXT:

customer profile inside CRM.



FEATURE:

AI lead score.



FOCUS:

surrounding profile information dims slightly while the score card moves

forward approximately one visual plane.



ACTION:

new lead data enters the card.



SYSTEM RESPONSE:

score calculates and recommendation appears.



RESULT:

high-intent status becomes the brightest element.



VALUE:

sales team immediately knows who should be contacted first.



TRANSITION:

recommendation expands into the next automation scene.



Now the shot communicates a product benefit instead of a click.



\---



\# 109. Golden Rule



A feature is not interesting because the user can click it.



A feature is interesting because something valuable happens after the action.



Always direct attention toward:



CONTEXT

→ ACTION

→ CONSEQUENCE

→ RESULT

→ VALUE



Show less interaction.



Show more meaning.
