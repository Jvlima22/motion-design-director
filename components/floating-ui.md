\# Floating UI



\## Purpose



Create spatial compositions where interface elements exist outside their

original flat layout while preserving hierarchy, product identity and

narrative meaning.



Floating UI is not:



RANDOM CARDS

\+

3D ROTATION

\+

GLOW

\+

PARALLAX.



Floating UI is:



HERO

→ SUPPORT

→ CONTEXT

→ DEPTH

→ RELATIONSHIP



Every floating element must justify its presence.



\---



\# 1. When to Use



Use Floating UI for:



\- SaaS hero sequences

\- product launches

\- AI platforms

\- feature ecosystems

\- integration scenes

\- dashboard cinematics

\- product breadth

\- multi-feature compositions

\- spatial transitions

\- premium technology films



\---



\# 2. Why It Works



A flat interface communicates usage.



A spatial interface can communicate:



SCALE



RELATIONSHIP



IMPORTANCE



ECOSYSTEM



COMPLEXITY



PREMIUM PERCEPTION



Use spatialization when one of these ideas matters.



\---



\# 3. Core Principle



Never ask:



"How many cards can we place around the product?"



Ask:



"What information deserves its own spatial layer?"



Each element needs:



ROLE



HIERARCHY



POSITION



DEPTH



RELATIONSHIP



\---



\# 4. Floating UI Roles



Classify each floating element as:



HERO



SUPPORT



CONTEXT



CONNECTOR



AMBIENT



Hero elements communicate the main idea.



Support explains the hero.



Context identifies the product/system.



Connectors explain relationships.



Ambient elements provide depth only.



\---



\# 5. The Card Soup Test



Remove every floating element one at a time.



Ask:



Does removing this element reduce:



UNDERSTANDING?



HIERARCHY?



CONTEXT?



DEPTH?



BRAND?



If not:



remove it.



\---



\# 6. Spatial Planes



Useful model:



FAR BACKGROUND



BACKGROUND



MIDGROUND



HERO PLANE



FOREGROUND



EXTREME FOREGROUND



Do not use every plane automatically.



\---



\# 7. Hero Plane



The hero should normally have:



\- strongest contrast

\- highest readability

\- most stable orientation

\- clearest lighting

\- intentional scale

\- sufficient negative space



Other planes support it.



\---



\# 8. Supporting Planes



Supporting UI may have:



\- smaller scale

\- lower contrast

\- greater perspective

\- partial cropping

\- reduced detail



Do not let support compete with hero.



\---



\# 9. Background Plane



Useful for:



\- product context

\- large dashboard

\- system environment

\- brand grid

\- low-priority information



Background UI does not need full readability.



\---



\# 10. Foreground Plane



Useful for:



\- depth

\- transition

\- framing

\- controlled occlusion



Foreground UI may be partially cropped.



It should not permanently hide the hero.



\---



\# 11. Depth Hierarchy



Depth should correspond to meaning.



Example:



FOREGROUND

incoming lead



HERO

AI qualification



MIDGROUND

CRM



BACKGROUND

automation system



Now spatial arrangement communicates process.



\---



\# 12. Spatial Relationships



Possible relationships:



CENTER + SATELLITES



LINEAR FLOW



RADIAL SYSTEM



LAYERED STACK



CORRIDOR



GRID



CLUSTER



INFINITE CANVAS



Choose according to product logic.



\---



\# 13. Center + Satellites



One hero at center.



Supporting elements surround it.



Best for:



\- AI core

\- platform hub

\- main product

\- central feature



Avoid perfectly symmetrical orbit unless concept requires it.



\---



\# 14. Linear Flow



Elements arranged according to process.



INPUT

→ PROCESS

→ OUTPUT



Best for:



\- automation

\- AI

\- lead flow

\- payments

\- workflows



Spatial direction should match narrative direction.



\---



\# 15. Radial System



Elements connect to central hub.



Best for:



\- integrations

\- ecosystems

\- agent systems



Center must actually represent the hub.



\---



\# 16. Layered Stack



Components occupy parallel depth planes.



Best for:



\- architecture

\- product layers

\- feature hierarchy

\- exploded interfaces



Maintain alignment.



\---



\# 17. Corridor



UI components form a path.



Camera travels through.



Best for:



\- feature journey

\- workflow

\- product exploration



Avoid long corridors without new information.



\---



\# 18. Grid



Floating elements retain grid logic.



Best for:



\- feature collections

\- interface mosaics

\- product breadth



Introduce depth without destroying alignment.



\---



\# 19. Cluster



Related components form groups.



Useful for:



\- departments

\- modules

\- AI agents

\- integrations



Cluster by meaning, not visual convenience.



\---



\# 20. Infinite Canvas



UI appears to extend beyond frame.



Useful for:



\- workflow builders

\- AI orchestration

\- automation platforms

\- complex systems



Viewer still needs a clear hero.



\---



\# 21. Composition



Design the shot first as a still frame.



Check:



HERO



SILHOUETTE



NEGATIVE SPACE



OVERLAP



DEPTH



SAFE AREAS



READABILITY



Only then animate.



\---



\# 22. Overlap



Overlap creates depth.



Useful:



foreground card partially overlaps hero edge.



Avoid:



important text overlapping other important content.



Overlap should clarify planes.



\---



\# 23. Cropping



Partial cropping can imply a larger world.



Good candidates:



supporting cards



foreground elements



background panels



Do not crop hero information accidentally.



\---



\# 24. Scale



Scale can reinforce depth.



Foreground may appear larger.



Background may appear smaller.



But semantic importance can override physical depth.



The hero should remain dominant.



\---



\# 25. Perspective



Use more perspective on support.



Use less perspective on readable hero UI.



Possible:



HERO

near frontal



SUPPORT

5–15° relative angle



AMBIENT

stronger angle



Conceptual guidance only.



\---



\# 26. Orientation



Avoid every card facing a different direction.



Define a shared spatial system.



For example:



all cards orient toward a common virtual camera.



This makes the environment coherent.



\---



\# 27. Camera



Useful camera behaviors:



STATIC



SLOW PUSH



SLOW PULL



LATERAL TRAVEL



ORBIT



FOLLOW



DEPTH TRAVEL



Camera should reveal spatial relationships.



\---



\# 28. Static Camera



Best when composition itself is strong.



Floating motion creates depth without camera competition.



Useful for premium hero shots.



\---



\# 29. Slow Push



Creates discovery.



Possible:



SUPPORT

→ HERO



Useful for introducing main feature.



\---



\# 30. Slow Pull



Reveals ecosystem.



Pattern:



HERO

→ SUPPORT

→ SYSTEM



Excellent for payoff.



\---



\# 31. Lateral Travel



Camera moves across spatial UI.



Creates parallax naturally.



Useful for:



\- multiple features

\- platform breadth

\- system exploration



\---



\# 32. Orbit



Use small orbit around hero.



Useful for:



\- product hero

\- AI core

\- spatial ecosystem



Avoid constant rotation.



\---



\# 33. Follow



Follow a meaningful object.



Example:



LEAD CARD

→ AI

→ CRM



This combines floating UI with narrative.



\---



\# 34. Depth Travel



Camera moves forward/backward through layers.



Useful for:



\- feature discovery

\- portals

\- product architecture



Maintain readable landing points.



\---



\# 35. Camera Restraint



If UI elements already have strong spatial motion:



camera should usually become simpler.



If camera is the hero:



reduce card movement.



\---



\# 36. Floating Motion



Floating does not mean constant bobbing.



Possible motion:



SUBTLE DRIFT



SETTLE



PARALLAX



RESPONSIVE SHIFT



TRIGGERED MOVEMENT



Some elements may remain completely still.



\---



\# 37. Subtle Drift



Useful for ambient life.



Keep:



slow



small



asynchronous



Avoid visible repetitive sine-wave movement on every card.



\---



\# 38. Responsive Shift



Cards move slightly in response to:



camera



hero movement



interaction



This creates a coherent system.



\---



\# 39. Triggered Movement



Support moves only when narrative event occurs.



Example:



AI activates

→ supporting data cards reposition

→ result card becomes hero



More meaningful than constant motion.



\---



\# 40. Parallax



Natural floating UI tool.



Relative motion:



FAR

small



MID

medium



NEAR

larger



Use consistent camera relationship.



\---



\# 41. Entry



Possible:



ASSEMBLE



DEPTH ARRIVAL



SIDE ARRIVAL



REVERSE EXPLOSION



MASK



FADE + MOVE



CAMERA DISCOVERY



Choose according to previous shot.



\---



\# 42. Assemble Entry



Cards arrive into a spatial composition.



Reveal order should follow hierarchy.



HERO first or last depending on narrative.



\---



\# 43. Depth Arrival



Components approach from deeper Z-space.



Useful for:



\- cinematic hero

\- ecosystem

\- AI product



Avoid cards flying directly at viewer aggressively.



\---



\# 44. Camera Discovery



Composition already exists.



Camera movement reveals it.



Often more premium than animating every card into frame.



\---



\# 45. Exit



Possible:



HERO DIVE



ECOSYSTEM PULL



REASSEMBLY



OCCLUSION



DATA FOLLOW



CARD EXPANSION



LOGO CONVERGENCE



Use one element to carry continuity.



\---



\# 46. Hero Dive



Camera approaches hero card until it becomes next scene.



Excellent for moving from ecosystem to feature.



\---



\# 47. Ecosystem Pull



Camera pulls away to reveal more system context.



Useful for payoff.



\---



\# 48. Reassembly



Floating components return to actual interface.



Useful for preserving product truth.



\---



\# 49. Occlusion Exit



Foreground card fills frame.



Hidden cut occurs.



Useful for seamless transitions.



\---



\# 50. Data Follow Exit



A data packet leaves one component.



Camera follows it.



Next scene begins at destination.



Excellent for automation/AI narratives.



\---



\# 51. Lighting



Lighting should define planes.



Possible:



HERO LIGHT



SUPPORT FALL-OFF



BACKGROUND AMBIENCE



EDGE LIGHT



ENVIRONMENTAL SPILL



Avoid identical glow on every card.



\---



\# 52. Hero Lighting



Hero may receive:



stronger edge



higher luminance



brand accent



local radial light



Keep content readable.



\---



\# 53. Supporting Lighting



Reduce intensity.



Support should feel present but secondary.



\---



\# 54. Glow



Use for active states.



Good:



AI card activates

→ temporary glow.



Bad:



all cards permanently glow.



\---



\# 55. Shadows



Shadows help establish physical separation.



Coordinate:



depth

→ shadow softness

→ shadow distance



Keep consistent virtual light direction.



\---



\# 56. Reflection



Useful for:



\- glass

\- device

\- premium hero panels



Avoid reflection on every interface surface.



\---



\# 57. Blur



Background/support can use mild depth blur.



Hero should remain sharp.



Do not rely on blur alone for hierarchy.



\---



\# 58. Atmosphere



Possible:



subtle grain



slow gradient



low-density particles



grid



haze



data traces



Atmosphere stays behind product hierarchy.



\---



\# 59. Connection Lines



Use when elements have functional relationships.



Examples:



AI ↔ tools



CRM ↔ integrations



trigger → workflow



Do not connect cards merely because they share the frame.



\---



\# 60. Connection Behavior



Useful sequence:



SOURCE ACTIVATES



→ CONNECTION APPEARS



→ DATA TRAVELS



→ DESTINATION ACTIVATES



This communicates causality.



\---



\# 61. Typography



Floating text should be treated carefully.



Use large statements separately from dense UI.



Avoid many floating labels competing with cards.



\---



\# 62. Labels



Labels may identify:



modules



layers



systems



integrations



Keep them spatially anchored.



Do not create detached text with unclear ownership.

\# 63. Sound

\# 64. Timing

\# 79. Complexity Rule



As element count increases:



reduce individual motion.



As element count decreases:



individual motion can become richer.



\---



\# 80. Readability Rule



Elements intended to be read should have:



stable orientation



sufficient size



sufficient contrast



limited blur



limited motion



Supporting elements can be less readable.



\---



\# 81. Safe Areas



For multi-format delivery,

Test:

9:16



1:1



Spatial composition should be adaptable.



\---



\# 82. Vertical Adaptation



Do not crop horizontal floating composition.

\---



\# 83. Card Soup Failure



Symptoms:



\- too many cards

\- equal scale

\- equal brightness

\- random rotation

\- random depth

\- constant drift



Fix:



choose one hero.



Group supports.



Remove unnecessary elements.



\---



\# 84. Orbit Soup Failure



Problem:



everything orbits everything.



Fix:



only use orbital relationships when system actually has central structure.



\---



\# 85. Parallax Soup Failure



Problem:



each card moves independently.



Fix:



derive movement from shared camera/depth model.



\---



\# 86. Glow Soup Failure



Problem:



every card emits light.



Fix:



glow active/hero elements only.



\---



\# 87. Glass Soup Failure



Problem:



every surface becomes transparent glass.



Fix:



use material hierarchy.



Some surfaces should remain solid.



\---



\# 88. Perspective Soup Failure



Problem:



each card uses a different arbitrary angle.



Fix:



define common spatial orientation.



\---



\# 89. Motion Soup Failure



Problem:



cards float, rotate, scale and glow simultaneously.



Fix:



one dominant motion behavior per layer.



\---



\# 90. Empty Space Fear



Do not fill every gap with another card.



Negative space makes spatial UI feel premium.

\# 103. Creative Director Rule



Do not request:



"Add floating cards around the dashboard."



Define:



HERO:

AI recommendation card.



SUPPORT:

customer profile and predicted LTV.



CONTEXT:

main CRM dashboard.



SPATIAL MODEL:

dashboard remains behind at low depth;

AI recommendation moves forward;

customer information sits slightly left and behind it.



CAMERA:

slow lateral move creates parallax.



ACTION:

AI recommendation activates,

then camera pushes into it for the next shot.



Now spatial composition explains product hierarchy.



\---



\# 104. Golden Rule



Floating UI should make relationships easier to understand,

not merely make a flat product look more complicated.



Every element needs a role.



Every plane needs a hierarchy.



Every movement needs a reason.



If a card exists only to fill space:



remove it.
