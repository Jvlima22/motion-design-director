\# Cursor Animation



\## Purpose



Use the cursor as a narrative instrument that directs attention,

establishes causality and demonstrates product interaction.



The cursor is not decoration.



It represents:



USER INTENT



ATTENTION



ACTION



CAUSE



PROGRESSION



A good cursor sequence makes the viewer understand:



WHERE TO LOOK

→ WHAT THE USER DOES

→ WHAT THE PRODUCT DOES NEXT



\---



\# 1. When to Use



Use cursor animation for:



\- SaaS demonstrations

\- desktop applications

\- web applications

\- dashboards

\- CRM systems

\- automation builders

\- AI tools

\- editors

\- drag-and-drop interfaces

\- search

\- command palettes

\- interactive feature demonstrations



\---



\# 2. When Not to Use



Avoid cursor animation when:



\- no user action needs explanation

\- system behavior is automatic

\- camera already clearly directs attention

\- sequence is purely conceptual

\- product is mobile/touch-first

\- cursor would create tutorial-like pacing

\- action can be communicated more elegantly through state change



\---



\# 3. Core Principle



The cursor should move only when user intent changes.



Do not animate the cursor because the screen contains another clickable item.



Every movement needs a destination and purpose.



\---



\# 4. Cursor Narrative



Default pattern:



TARGET INTRODUCED



→ CURSOR APPROACHES



→ TARGET RESPONDS



→ ACTION



→ PRODUCT RESPONDS



→ CURSOR BECOMES SECONDARY



The product response is the payoff.



\---



\# 5. Cursor Roles



Cursor may function as:



POINTER



TRIGGER



GUIDE



SELECTOR



DRAGGER



SCRUBBER



DRAWING TOOL



CAMERA GUIDE



TRANSITION DEVICE



Choose role intentionally.



\---



\# 6. Pointer



Simply directs attention.



No click required.



Useful for:



\- identifying feature

\- moving viewer attention

\- showing location



Keep movement subtle.



\---



\# 7. Trigger



Cursor causes product state change.



Pattern:



MOVE

→ HOVER

→ CLICK

→ RESPONSE



Most common role.



\---



\# 8. Guide



Cursor leads viewer through interface.



Useful for:



\- workflow

\- builder

\- complex UI



Do not visit unnecessary elements.



\---



\# 9. Selector



Used for:



\- dropdown

\- menu

\- list

\- filter

\- text

\- object



Selection should have clear visual feedback.



\---



\# 10. Dragger



Used for:



\- drag-and-drop

\- node connections

\- cards

\- files

\- timeline

\- sliders



The object being dragged becomes more important than cursor.



\---



\# 11. Scrubber



Useful for:



\- timeline

\- media

\- charts

\- before/after

\- history



Cursor motion should map directly to changing state.



\---



\# 12. Drawing Tool



Useful for:



\- design tools

\- whiteboards

\- annotation

\- creative software



Cursor may transform into tool-specific state.



\---



\# 13. Camera Guide



Cursor moves toward feature.



Camera subtly follows or reframes.



Use carefully.



Cursor should not feel like it physically controls camera unless intended.



\---



\# 14. Transition Device



Cursor interaction can trigger next shot.



Example:



CURSOR CLICKS CARD



→ CARD EXPANDS



→ NEXT SCENE



Strong shared-element transition.



\---



\# 15. Cursor States



Useful states:



IDLE



MOVING



HOVER



PRESSED



DRAGGING



TEXT



RESIZE



SELECT



HIDDEN



State should match actual interaction.



\---



\# 16. Idle



Cursor should usually remain still.



Do not add constant micro-motion.



Stillness communicates waiting.



\---



\# 17. Moving



Movement should have:



clear origin



clear destination



intentional path



appropriate speed



\---



\# 18. Hover



Target may respond before click.



Possible:



border



fill



scale



shadow



tooltip



highlight



Keep response faithful to product when possible.



\---



\# 19. Pressed



Click should have brief tactile state.



Possible:



cursor scale



target compression



ripple



highlight



sound



Do not over-animate simple click.



\---



\# 20. Dragging



Cursor and object become temporarily coupled.



Maintain:



offset



path



object state



drop target



\---



\# 21. Text Cursor



Use appropriate text-selection / insertion representation when necessary.



Avoid generic arrow when product interaction clearly requires text cursor.



\---



\# 22. Cursor Visibility



Cursor does not need to remain visible throughout entire video.



Hide when:



\- camera becomes hero

\- system processes

\- result is being read

\- product behavior is automatic

\- cursor no longer contributes



\---



\# 23. Movement Path



Possible:



DIRECT



CURVED



ORTHOGONAL



ARC



MULTI-POINT



Choose shortest believable path unless path itself communicates something.



\---



\# 24. Direct Path



Best default.



Efficient.



Clear.



Professional.



\---



\# 25. Curved Path



Adds softness and human feel.



Useful for:



premium product videos



large movement



Avoid exaggerated curves.



\---



\# 26. Arc



Useful when avoiding important content.



Path should not cross hero information unnecessarily.



\---



\# 27. Multi-Point Movement



Use only when cursor performs multiple intentional actions.



Do not create sightseeing tours around UI.



\---



\# 28. Cursor Speed



Cursor speed communicates confidence.



Too slow:



tutorial.



Too fast:



unreadable.



Aim for:



DECISIVE

but

TRACKABLE.



\---



\# 29. Distance-Based Timing



Longer travel should generally take longer than short travel.



But not linearly.



A cursor crossing full screen should not feel painfully slow.



Use distance-aware timing.



\---



\# 30. Acceleration



Cursor movement should normally:



accelerate

→ travel

→ decelerate.



Avoid perfectly linear robotic movement unless visual language demands it.



\---



\# 31. Landing



Cursor should decelerate into target.



This prepares viewer for action.



Avoid:



FAST MOVE

→ INSTANT CLICK



without visual landing.



\---



\# 32. Pre-Click Hold



A tiny hold before click can improve comprehension.



Especially when:



target is small



interface is dense



feature is important



Do not overdo it.



\---



\# 33. Post-Click Behavior



After click:



cursor should usually stop or move out of attention.



Allow product response to become hero.



\---



\# 34. Cursor Scale



Cursor may scale slightly for visibility.



Keep proportion believable.



Avoid oversized tutorial cursor unless accessibility or style requires it.



\---



\# 35. Cursor Contrast



Cursor must remain visible across:



light UI



dark UI



mixed backgrounds.



Possible:



outline



shadow



adaptive treatment



Do not make cursor visually louder than feature.



\---



\# 36. Cursor Style



Possible:



SYSTEM-LIKE



BRANDED



MINIMAL



HIGH-CONTRAST



TOOL-SPECIFIC



Use style consistent with product film.



\---



\# 37. Branded Cursor



Brand accent may appear subtly.



Do not turn cursor into logo unless concept requires it.



\---



\# 38. Cursor Shadow



Small shadow can separate cursor from interface.



Keep subtle.



\---



\# 39. Cursor Trail



Use only when trail communicates:



speed



direction



technology



energy



Trail should decay quickly.



Avoid permanent glowing comet cursor.



\---



\# 40. Trail Types



Possible:



MOTION BLUR



SHORT GHOST



LIGHT TRAIL



PARTICLE TRAIL



VECTOR TRAIL



Use minimally.



\---



\# 41. Cursor Focus Ring



A temporary ring may emphasize action.



Useful for:



marketing demo



small targets



accessibility-oriented demonstration



Avoid on every click.



\---



\# 42. Click Feedback



Possible:



TARGET STATE CHANGE



CURSOR COMPRESSION



RIPPLE



RING



FLASH



SOUND



Usually one or two cues are enough.



\---



\# 43. Cursor Compression



Tiny scale-down on press.



Then restore.



Can add tactile feel without visual clutter.



\---



\# 44. Target Compression



Button/card may respond instead.



Often better than animating cursor heavily.



\---



\# 45. Ripple



Useful when click location needs emphasis.



Keep small and fast.



Avoid generic tutorial ripple everywhere.



\---



\# 46. Double Click



Only show if actual behavior requires it.



Do not use double click for visual excitement.



\---



\# 47. Right Click



Show contextual menu if feature requires it.



Make menu response the payoff.



\---



\# 48. Hover Reveal



Pattern:



CURSOR APPROACHES



→ TARGET HOVER



→ ADDITIONAL INFORMATION APPEARS



Useful for:



tooltips



menus



previews



\---



\# 49. Dropdown Interaction



Pattern:



CURSOR

→ CONTROL

→ CLICK

→ MENU

→ OPTION

→ RESULT



Compress unnecessary travel.



\---



\# 50. Search Interaction



Pattern:



CURSOR

→ SEARCH

→ CLICK

→ TYPE

→ RESULTS

→ SELECT / RESULT



Cursor becomes secondary during typing.



\---



\# 51. Command Palette



Pattern:



TRIGGER



→ PALETTE



→ TYPE



→ RESULT



Keyboard shortcut may replace cursor entirely.



Do not force cursor into keyboard-centric interaction.



\---



\# 52. Typing



Cursor may click input.



Then:



TEXT becomes hero.



Avoid moving cursor while typing unless needed.



\---



\# 53. Typing Speed



Readable.



Confident.



Do not type every character slowly in long prompts.



Possible:



type key phrase



jump/compress



show completed text.



\---



\# 54. Text Selection



Use when selection itself matters.



Pattern:



CURSOR DRAGS



→ TEXT SELECTED



→ ACTION



Keep selection path precise.



\---



\# 55. Drag-and-Drop



Pattern:



CURSOR APPROACHES



→ PRESS



→ OBJECT LIFTS



→ DRAG



→ DROP TARGET RESPONDS



→ RELEASE



→ RESULT



\---



\# 56. Drag Object Lift



When drag begins,

object may:



scale slightly



gain shadow



move above plane



This communicates attachment.



\---



\# 57. Drop Target



Target should respond before release.



Possible:



highlight



expand



outline



snap zone



This makes destination clear.



\---



\# 58. Drop Result



After release:



object settles



system updates



result appears



Do not end sequence at mouse-up.



\---



\# 59. Node Connection



Excellent for automation builders.



Pattern:



CURSOR

→ PORT

→ PRESS

→ CONNECTION FOLLOWS

→ DESTINATION PORT

→ RELEASE

→ FLOW ACTIVATES



\---



\# 60. Slider



Cursor movement must map to value.



Show meaningful result.



Example:



THRESHOLD CHANGES

→ CHART / RESULT UPDATES.



\---



\# 61. Timeline Scrub



Cursor movement and media/time state should remain synchronized.



Avoid arbitrary timeline movement.



\---



\# 62. Scroll



Scroll should reveal something meaningful.



Pattern:



SCROLL

→ NEW SECTION

→ FEATURE



Do not scroll long pages merely to show movement.



\---



\# 63. Scroll Indicator



Cursor itself may remain still while page moves.



This often looks cleaner.



Use wheel/gesture implication only if necessary.



\---



\# 64. Horizontal Scroll



Use only when product actually supports it.



Maintain direction clarity.



\---



\# 65. Cursor + Camera



Hierarchy:



CURSOR ACTION

or

CAMERA ACTION



not both at maximum intensity.



\---



\# 66. Camera Follow



Camera may subtly reframe after cursor establishes target.



Pattern:



CURSOR TARGETS

→ CAMERA FOLLOWS

→ CURSOR STOPS

→ FEATURE ACTION



\---



\# 67. Camera Push After Click



Strong pattern:



CLICK

→ FEATURE ACTIVATES

→ CAMERA PUSHES INTO RESULT



Cursor disappears.



\---



\# 68. Cursor During Camera Move



If camera moves strongly,

cursor may:



remain attached to UI coordinates



fade



hide



Avoid cursor appearing to slide independently because of incorrect coordinate space.



\---



\# 69. Cursor + Feature Focus



Natural pairing.



CURSOR

→ TARGET

→ CLICK

→ SURROUNDING UI RECEDES

→ FEATURE BECOMES HERO



\---



\# 70. Cursor + Data Flow



Cursor triggers flow.



Then data movement becomes hero.



CURSOR

→ CLICK

→ SIGNAL

→ SYSTEM



Cursor should not chase signal.



\---



\# 71. Cursor + UI Explosion



Possible:



cursor selects feature



→ interface separates



→ selected layer remains hero.



Use when interaction motivates structural reveal.



\---



\# 72. Cursor + Floating UI



Cursor may interact with hero plane.



Avoid moving cursor across multiple depth planes unrealistically.



\---



\# 73. Cursor + Device



Desktop/laptop:



cursor appropriate.



Phone/watch:



prefer touch.



Tablet depends on product/context.



\---



\# 74. Cursor + Typography



Typography can explain value while cursor demonstrates action.



Avoid explanatory text that merely narrates mouse movement.



\---



\# 75. Cursor + Sound



Useful sounds:



soft movement accent



hover



click



drag pickup



drop



confirmation



Do not add sound to every pixel of movement.



\---



\# 76. Click Sound



Should feel:



short



tactile



appropriate to brand.



Avoid exaggerated mechanical mouse sound unless desired.



\---



\# 77. Hover Sound



Usually unnecessary.



Use only for stylized/high-value hover moment.



\---



\# 78. Drag Sound



Possible:



pickup cue



soft movement texture



drop cue



Keep subtle.



\---



\# 79. Interaction Rhythm



Cursor movement can align with music.



But usability logic takes priority.



Do not click random controls on beat.



\---



\# 80. Beat-Synced Click



Useful when:



action itself is meaningful



music impact aligns naturally.



Avoid repetitive beat-click montage.



\---



\# 81. Cursor Sequence



For multiple interactions:



ACTION 1

→ RESULT



ACTION 2

→ RESULT



ACTION 3

→ RESULT



Do not:



click

click

click

then show all results.



\---



\# 82. Cursor Efficiency



The cursor should travel the minimum narrative distance.



If target is far away,

consider:



reframe



cut



shared-element transition



instead of long cursor travel.



\---



\# 83. Cursor and Eye Tracking



Cursor attracts attention strongly.



Do not place important typography opposite a moving cursor simultaneously.



Viewer cannot prioritize both.



\---



\# 84. Cursor Entry



Possible:



ALREADY PRESENT



FADE



ENTER FROM EDGE



APPEAR NEAR TARGET



Choose based on continuity.



Avoid dramatic cursor entrance unless cursor itself is concept.



\---



\# 85. Cursor Exit



Possible:



STOP



FADE



LEAVE FRAME



HIDE DURING TRANSITION



Usually subtle.



\---



\# 86. Cursor Continuity



Across cuts,

cursor position should not jump confusingly if same interaction continues.



Match:



position



direction



state.



\---



\# 87. Cursor Match Cut



Cursor location can bridge shots.



Example:



cursor clicks same relative position

→ new UI appears.



Useful for product montage.



\---



\# 88. Cursor as Wipe



Rare stylized technique.



Cursor drags/resizes object that fills frame,

creating transition.



Must derive from actual interaction metaphor.



\---



\# 89. Cursor as Shared Element Trigger



Excellent pattern:



CURSOR CLICKS CARD



→ CARD EXPANDS



→ CURSOR DISAPPEARS



→ NEXT SCENE



The click motivates transition.

\# 96. Developer Tool Pattern

keyboard

\---



\# 97. Tutorial vs Product Film



Tutorial asks:



"Where do I click?"



Product film asks:



"What becomes possible?"



Cursor usage should reflect product-film goal.



\---



\# 98. Avoid — Cursor Tourism



Problem:



cursor visits multiple controls without meaningful results.



Fix:



only show actions that advance story.



\---



\# 99. Avoid — Slow Cursor



Problem:



every movement takes too long.



Fix:



decisive distance-aware movement.



\---



\# 100. Avoid — Teleporting Cursor



Problem:



cursor instantly appears at unrelated targets.



Fix:



use:



movement



cut



reframe



or intentional disappearance/re-entry.



\---



\# 101. Avoid — Click Without Hover



For important interactions,

small landing/hover often improves causality.



Not mandatory for rapid montage.



\---



\# 102. Avoid — Click Without Response



Every important click needs visible consequence.



\---



\# 103. Avoid — Result Without Trigger



If user action matters,

establish it before response.



\---



\# 104. Avoid — Oversized Cursor



Problem:



cursor becomes hero unintentionally.



Fix:



maintain product-relative scale.



\---



\# 105. Avoid — Excessive Ripple



Problem:



every click has giant ripple.



Fix:



reserve emphasis for important action.



\---



\# 106. Avoid — Constant Trail



Problem:



cursor looks like gaming effect.



Fix:



trail only when motion language justifies it.



\---



\# 107. Avoid — Wrong Interaction



Do not show:



hover on touch-only UI



cursor on phone



drag where product uses click



fake gestures.



Preserve product truth.



\---



\# 108. Avoid — Cursor Competing With Camera



Sequence them.



CURSOR

then

CAMERA



or



CAMERA

then

CURSOR.



\---



\# 109. Avoid — Cursor Competing With Result



Once result appears,

reduce cursor prominence.

\# 110. Motion Model

→ ACCELERATE



→ CRUISE



→ DECELERATE



→ LAND



→ ACTION

\---



\# 111. Duration Model



Base movement duration on:



distance



importance



density



target size



A tiny move should not take as long as crossing entire dashboard.



\---



\# 112. Target Size



Smaller targets benefit from slightly clearer landing.



Large hero cards can accept faster approach.



\---



\# 113. Path Planning



Before animating define:



START



TARGET



OBSTACLES



HERO CONTENT



CAMERA



Choose path that does not cross important information unnecessarily.



\---



\# 114. Motion Restraint



A cursor is already a powerful attention cue.



It often needs fewer additional effects than expected.



\---



\# 115. Remotion Strategy



Create reusable cursor primitive.



Possible:



<Cursor

&#x20; position={position}

&#x20; state={state}

&#x20; visible={visible}

/>



Drive position from semantic interaction timeline.



\---



\# 116. Remotion Interaction Model



Represent actions as events.



Conceptual:



\[

&#x20; {

&#x20;   type: "move",

&#x20;   target: "ai-button"

&#x20; },

&#x20; {

&#x20;   type: "click",

&#x20;   target: "ai-button"

&#x20; },

&#x20; {

&#x20;   type: "wait",

&#x20;   duration: 20

&#x20; }

]



This is better than manually coding unrelated X/Y values throughout scene.



\---



\# 117. Remotion Coordinate System



Prefer targets derived from layout positions.



Avoid hard-coded cursor coordinates when possible.



Cursor should track component position if layout changes.



\---



\# 118. Remotion Movement



Use interpolation or spring depending on style.



For cursor travel:



controlled easing is often preferable to bouncy spring.



Cursor should feel intentional.



\---



\# 119. Remotion Click State



Define:



PRESS\_START



PRESS\_END



RESULT\_START



Animate:



cursor state



target state



sound



system response



from shared timing.



\---



\# 120. Remotion Drag



Bind object position to cursor progress during drag.



Maintain initial click offset.



Do not snap object center to cursor unless actual product does.



\---



\# 121. Remotion Path



For complex motion,

use Bezier/path sampling.



For simple movement,

interpolated X/Y is sufficient.



Do not over-engineer.

\# 132. Creative Director Rule



Do not say:



"Move the cursor to the AI button and click."



Define:



START:

cursor rests near customer profile.



TARGET:

AI qualification action.



PATH:

short curved movement avoiding customer name.



LANDING:

cursor decelerates into target and button enters hover state.



ACTION:

single click.



RESPONSE:

cursor remains still while qualification card expands.



RESULT:

AI score and recommendation become visual hero.



EXIT:

cursor fades as camera pushes toward recommendation.



Now cursor establishes causality,

then gives attention back to the product.



\---



\# 133. Golden Rule



The cursor represents user intention.



It should never move without intention.



Use it to establish:



WHERE THE USER ACTS



WHAT THE USER DOES



WHAT THE PRODUCT DOES BECAUSE OF IT



Then get the cursor out of the way.



ACTION IS THE TRIGGER.



PRODUCT VALUE IS THE HERO.
