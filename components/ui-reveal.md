\# UI Reveal



\## Purpose



Reveal a product interface in a controlled, hierarchical and cinematic way.



UI Reveal should answer:



WHAT IS THE PRODUCT?



WHERE SHOULD THE VIEWER LOOK FIRST?



HOW MUCH OF THE INTERFACE SHOULD BE UNDERSTOOD NOW?



The goal is not to animate every UI element.



The goal is to introduce the interface with intentional hierarchy.



\---



\# 1. When to Use



Use UI Reveal for:



\- SaaS product introductions

\- dashboard reveals

\- application launches

\- feature introductions

\- web platform demonstrations

\- AI product interfaces

\- transitions from abstract visuals into real product

\- device-to-interface sequences

\- section resets where product context must be restored



\---



\# 2. Why It Works



A complete interface contains too much information to absorb instantly.



A controlled reveal establishes:



CONTEXT

→ HIERARCHY

→ HERO

→ SUPPORT

→ DETAIL



This reduces cognitive load while making the product feel more intentional.



\---



\# 3. Core Structure



Default structure:



ENVIRONMENT

→ PRODUCT FRAME

→ PRIMARY STRUCTURE

→ HERO FEATURE

→ SUPPORTING UI

→ DETAIL

→ HOLD



Alternative:



HERO FEATURE

→ SUPPORTING CONTEXT

→ FULL PRODUCT



Choose based on whether the viewer needs context first or impact first.



\---



\# 4. Hierarchy



Classify interface elements as:



HERO



SUPPORT



CONTEXT



AMBIENT



Example:



HERO

main analytics chart



SUPPORT

metric cards



CONTEXT

navigation



AMBIENT

secondary rows and labels



Reveal according to hierarchy.



Do not give equal animation weight to every layer.



\---



\# 5. Base Composition



Before animation, create a frame that already works as a still image.



Check:



\- focal point

\- negative space

\- visual weight

\- product readability

\- safe areas

\- typography

\- contrast



Motion cannot rescue weak composition.



\---



\# 6. Reveal Order



Useful default:



1\. product container

2\. navigation/context

3\. hero feature

4\. supporting components

5\. secondary details

6\. ambient elements



But story determines order.



If the feature itself is the hook:



FEATURE

→ CONTEXT

→ PRODUCT



may be stronger.



\---



\# 7. Clean Reveal



\## Character



Precise, restrained and product-first.



\## Structure



UI FRAME

→ HERO

→ SUPPORT

→ HOLD



\## Motion



\- opacity

\- small translation

\- subtle scale

\- controlled stagger



\## Camera



Static or minimal push.



\## Best For



\- enterprise SaaS

\- finance

\- productivity

\- professional tools



\---



\# 8. Cinematic Reveal



\## Character



Premium and dimensional.



\## Structure



ENVIRONMENT

→ PRODUCT SILHOUETTE

→ LIGHT

→ UI

→ HERO



\## Motion



\- camera push

\- depth separation

\- controlled lighting

\- subtle parallax



\## Best For



\- launch films

\- hero moments

\- premium SaaS

\- AI products



Product readability must remain dominant.



\---



\# 9. Perspective Reveal



Start with interface at an angle.



Pattern:



ANGLED UI

→ CAMERA APPROACHES

→ INTERFACE REVEALS

→ CAMERA FLATTENS

→ READABLE PRODUCT



Useful for moving from cinematic presentation to product demonstration.



\---



\# 10. Depth Reveal



Pattern:



BACKGROUND

→ SUPPORT PLANES

→ HERO PLANE

→ FOREGROUND DETAIL



Use Z-space to establish hierarchy.



Do not assign random depth.



Every plane needs a role.



\---



\# 11. Mask Reveal



Reveal UI through:



\- product frame

\- card

\- geometry

\- device screen

\- brand shape

\- viewport boundary



Useful for precise technology-oriented motion.



\---



\# 12. Progressive Reveal



Pattern:



STRUCTURE

→ PRIMARY FEATURE

→ SUPPORT

→ DETAILS

→ COMPLETE PRODUCT



Best for complex dashboards.



Avoid revealing everything simultaneously.



\---



\# 13. Spatial Reveal



Interface components exist in dimensional space before forming the product.



Pattern:



COMPONENTS

→ ALIGN

→ ASSEMBLE

→ COMPLETE UI



Useful for:



\- high-end product launches

\- modular products

\- AI platforms



Maintain structural logic.



\---



\# 14. Device Reveal



Pattern:



DEVICE

→ SCREEN ACTIVATES

→ UI APPEARS

→ CAMERA APPROACHES

→ PRODUCT EXPERIENCE



Useful for mobile apps and wearables.



\---



\# 15. Logo-to-UI Reveal



Pattern:



LOGO

→ BRAND GEOMETRY

→ COMPONENTS

→ PRODUCT



Useful for branded openings.



The transformation should derive from actual brand geometry where possible.



\---



\# 16. Abstract-to-UI Reveal



Pattern:



ABSTRACT CONCEPT

→ STRUCTURE

→ PRODUCT ELEMENTS

→ REAL UI



Useful for AI and technology storytelling.



Return to recognizable product quickly enough to preserve credibility.



\---



\# 17. Blur-to-UI Reveal



Pattern:



ABSTRACT / BLURRED STATE

→ STRUCTURE EMERGES

→ HERO SHARPENS

→ FULL UI SHARPENS



Useful for discovery and focus.



Avoid excessive blur.



\---



\# 18. Light-to-UI Reveal



Pattern:



DARK / LOW INFORMATION

→ LIGHT SOURCE

→ PRODUCT SILHOUETTE

→ UI

→ HERO



Useful for premium product introductions.



Do not sacrifice text contrast.



\---



\# 19. Camera



Choose camera according to purpose.



\## Static



Best for clarity.



\## Slow Push



Adds importance and discovery.



\## Pull-Out



Useful when beginning from detail.



\## Perspective Flatten



Useful when transitioning from hero presentation to readable demo.



\## Mild Orbit



Useful for dimensional product hero.



Avoid strong camera movement during dense UI reading.



\---



\# 20. Camera Landing



Camera should settle before important interaction.



Pattern:



CAMERA MOVE

→ SETTLE

→ READ

→ ACTION



Not:



CAMERA

\+

CURSOR

\+

CHART

\+

TEXT

all moving simultaneously.



\---



\# 21. Motion



Primary motion should establish structure.



Possible:



\- translation

\- scale

\- opacity

\- mask

\- depth

\- assembly

\- shared element



Secondary motion may include:



\- chart animation

\- counters

\- cursor

\- ambient UI

\- background



Primary and secondary motion should not compete.



\---



\# 22. Stagger



Use stagger for related elements.



Example:



CARD 1

→ CARD 2

→ CARD 3



Do not stagger every interface object individually.



Group elements semantically.



\---



\# 23. Depth



Possible layers:



BACKGROUND

environment



MIDGROUND

product frame



HERO

important feature



FOREGROUND

optional transition/detail



Depth must reinforce hierarchy.



\---



\# 24. Lighting



Lighting can reveal structure.



Possible:



ENVIRONMENT LIGHT



PRODUCT EDGE LIGHT



HERO ACTIVATION



AMBIENT SPILL



Keep interface itself readable.



\---



\# 25. Effects



Strong defaults:



\- subtle shadow

\- controlled glow

\- mask

\- parallax

\- soft bloom

\- foreground occlusion

\- subtle grain



Avoid stacking all of them.



Choose according to visual problem.



\---



\# 26. Transition In



Possible:



CLEAN CUT



LOGO → UI



DEVICE → UI



ABSTRACT → UI



PUSH-THROUGH



MASK



OCCLUSION



MATCH CUT



Choose according to previous shot.



\---



\# 27. Transition Out



Useful:



FEATURE EXTRACTION



CARD EXPANSION



CAMERA PUSH



CURSOR INTERACTION



DATA FLOW



UI EXPLOSION



PULL-OUT



SHARED ELEMENT



The reveal should prepare the next shot.



\---



\# 28. Sound



Possible sound layers:



AMBIENCE

→ establishes environment



SOFT RISER

→ supports reveal



TACTILE UI

→ supports component arrival



LANDING

→ reinforces completion



Avoid one sound for every component.



\---



\# 29. Timing



Useful starting structure:



ENVIRONMENT

10–20%



PRIMARY REVEAL

20–35%



HERO REVEAL

20–30%



SUPPORT

10–20%



HOLD

15–30%



Adjust according to information density.



\---



\# 30. Hold



The final UI state must remain visible.



Do not transition away immediately after completing the reveal.



The viewer needs time to understand:



\- product

\- hierarchy

\- hero feature

\---



\# 38. Avoid When



Avoid elaborate UI Reveal when:



\- viewer already knows the interface

\- shot is only a quick proof point

\- sequence requires immediate action

\- UI is too information-dense for dimensional treatment

\- reveal delays the actual message



Sometimes a clean cut to the product is better.



\---



\# 39. Failure Mode — Everything Appears



Problem:



all interface elements animate simultaneously.



Fix:



define hierarchy and reveal groups.



\---



\# 40. Failure Mode — Everything Staggers



Problem:



every small component receives its own entrance.



Result:



slow, template-like motion.



Fix:



stagger meaningful groups.



\---



\# 41. Failure Mode — Too Much Perspective



Problem:



UI looks cinematic but cannot be read.



Fix:



flatten before important information.



\---



\# 42. Failure Mode — No Hold



Problem:



reveal finishes and immediately transitions.



Fix:



provide information hold.



\---



\# 43. Failure Mode — Generic Reveal



Problem:



every product uses:



fade

\+

scale

\+

glow.



Fix:



derive reveal from:



brand

product architecture

feature

story.



\---



\# 44. Failure Mode — Camera Competition



Problem:



camera continues moving during critical interaction.



Fix:



settle camera first.



\---



\# 45. Failure Mode — Fake Complexity



Problem:



unnecessary cards and layers are added to make product appear advanced.



Fix:



use actual product structure.



\---



\# 46. Failure Mode — Product Identity Lost



Problem:



interface becomes abstract geometry.



Fix:



preserve recognizable:



layout

colors

typography

components

navigation.

\# 47. Remotion Strategy



Prefer composition from reusable layers.



Possible structure:



ProductReveal

├── Environment

├── ProductFrame

├── Navigation

├── HeroFeature

├── SupportingUI

├── Cursor

└── Foreground



Drive timing from frames.



Use:



\- interpolate

\- spring

\- Sequence

\- AbsoluteFill

\- transforms

\- opacity

\- SVG masks



Prefer transforms over unnecessary raster manipulation.



\---



\# 48. Remotion Timing Strategy



Define semantic timings.



Example:



REVEAL\_START



FRAME\_IN



HERO\_IN



SUPPORT\_IN



INTERACTION\_START



HOLD\_START



OUT\_START



Avoid unexplained magic frame numbers scattered throughout components.

\# 50. After Effects Strategy



Prepare UI as separate structural layers.



Recommended:



PRODUCT\_FRAME



NAVIGATION



HERO



SUPPORT



DETAIL



CURSOR



ENVIRONMENT



Use:



\- precomps

\- null controllers

\- parent hierarchy

\- graph editor

\- masks

\- 3D layers

\- cameras

\---

Useful master controls:

HERO\_EMPHASIS



GLOW



BLUR

\---



\# 52. DaVinci Strategy



Use DaVinci primarily for:



\- editorial timing

\- compositing finished UI renders

\- sound design

\- transitions between rendered sequences

\- color finishing

\- final pacing



Fusion can support:



\- masks

\- planar transforms

\- glow

\- compositing

\- camera-style moves



For complex programmatic UI animation,

Remotion or After Effects may be more appropriate.

\# 55. Review Checklist



\[ ] Product is recognizable



\[ ] Hero feature is obvious



\[ ] Reveal order reflects hierarchy



\[ ] Composition works without motion



\[ ] Camera has a purpose



\[ ] Camera settles before reading



\[ ] Perspective preserves readability



\[ ] Supporting elements remain secondary



\[ ] Effects are restrained



\[ ] Final state receives enough hold



\[ ] Transition out is prepared



\[ ] Sound does not over-emphasize minor elements



\[ ] Product behavior remains truthful



\---



\# 56. Golden Rule



Reveal information in the order the viewer needs to understand it.



Do not animate the interface because it exists.



Animate the hierarchy.



The reveal is complete when the viewer knows:



WHAT THE PRODUCT IS



WHERE TO LOOK



WHAT MATTERS



WHAT HAPPENS NEXT
