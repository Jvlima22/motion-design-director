\# Data Flow



\## Purpose



Visualize the movement, transformation, routing and consequence of information

between product components, services, users, agents, integrations or systems.



Data Flow should communicate:



SOURCE

→ TRANSPORT

→ PROCESS

→ DESTINATION

→ RESPONSE



It is not:



RANDOM GLOWING LINES

\+

PARTICLES

\+

NODES.



Every moving signal must represent something.



\---



\# 1. When to Use



Use Data Flow for:



\- automation platforms

\- AI systems

\- agent workflows

\- APIs

\- integrations

\- CRM automation

\- data pipelines

\- payment systems

\- analytics

\- synchronization

\- event-driven systems

\- lead processing

\- messaging

\- cloud products

\- multi-device synchronization



\---



\# 2. Core Question



Before designing a data flow answer:



WHAT MOVES?



FROM WHERE?



TO WHERE?



WHY?



WHAT HAPPENS DURING TRANSPORT?



WHAT CHANGES AT DESTINATION?



WHAT RESULT DOES THE USER SEE?

\# 149. Creative Director Rule



Do not say:



"Connect the apps with glowing lines."



Define:



SOURCE:

website lead form.



SIGNAL:

lead card.



PATH:

lead moves into qualification system.



PROCESS:

AI score appears while supporting data is added.



DESTINATION:

CRM contact.



RESULT:

high-intent lead activates an automated WhatsApp follow-up.



CAMERA:

follows the lead from qualification toward CRM,

then stops before the result.



VISUAL HIERARCHY:

only the currently active connection uses brand accent;

all inactive topology remains neutral.



Now the flow explains what the product does.

\# 150. Golden Rule



Data movement must communicate causality.



Always know:



WHAT MOVED



WHERE IT CAME FROM



WHERE IT WENT



WHAT HAPPENED TO IT



WHAT CHANGED BECAUSE OF IT



If the viewer only sees beautiful moving lines,
