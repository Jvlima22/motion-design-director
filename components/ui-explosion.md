\# UI Explosion



\## Purpose



Separate a complete interface into meaningful spatial layers or components

to reveal structure, architecture, hierarchy or product complexity.



UI Explosion is not:



"make every card fly around."



It is:



COMPLETE PRODUCT

→ STRUCTURAL SEPARATION

→ RELATIONSHIP REVEAL

→ INSIGHT

→ RESOLUTION



Every separated element must have a reason to separate.



\---



\# 1. Three Related Patterns



Do not confuse:



UI EXPLOSION



UI DECOMPOSITION



EXPLODED VIEW



They may look similar,

but they communicate different ideas.



\---



\# 2. UI Explosion



Primary goal:



VISUAL IMPACT

\+

STRUCTURAL REVEAL



The interface separates dramatically while preserving recognizable

relationships.



Best for:



\- launch films

\- hero moments

\- feature ecosystems

\- transitions

\- high-impact SaaS sequences



\---



\# 3. UI Decomposition



Primary goal:



EXPLANATION



The interface separates according to functional groups.



Example:



DASHBOARD

→ ANALYTICS

→ CRM

→ AUTOMATION

→ AI

→ INTEGRATIONS



Best for:



\- platform explanation

\- architecture

\- modular products

\- feature categories



Clarity is more important than spectacle.



\---



\# 4. Exploded View



Primary goal:



SPATIAL ARCHITECTURE



Inspired by technical exploded diagrams.



Layers remain aligned while separating in space.



Example:



FRONT UI

→ INTERACTION LAYER

→ DATA LAYER

→ AUTOMATION LAYER

→ AI LAYER



Best for:



\- technical storytelling

\- system architecture

\- infrastructure

\- AI platforms



\---



\# 5. When to Use



Use when the viewer needs to understand:



\- what the product contains

\- how modules relate

\- how layers interact

\- how a system is constructed

\- where a feature belongs

\- how complexity becomes organized



Also useful as a hero visual when product architecture itself is impressive.



\---



\# 6. Avoid When



Avoid when:



\- interface is already visually simple

\- separation does not reveal new information

\- product must be read in detail

\- sequence already contains excessive depth

\- effect exists only for spectacle



A flat interface may communicate better.



\---



\# 7. Core Principle



Never separate UI by arbitrary DOM/component boundaries.



Separate by:



FUNCTION



HIERARCHY



NARRATIVE ROLE



SYSTEM LAYER



USER FLOW



The visual structure should explain the product.



\---



\# 8. Structural Analysis



Before animation identify:



BASE



NAVIGATION



PRIMARY FEATURE



SECONDARY FEATURES



DATA



INTERACTION



SYSTEM



OVERLAYS



BRAND



Then decide which groups need independent spatial behavior.



\---



\# 9. Explosion Axis



Choose a dominant separation axis.



Possible:



Z-DEPTH



HORIZONTAL



VERTICAL



RADIAL



DIAGONAL



FUNCTIONAL CLUSTERS



Avoid random multidirectional movement unless chaos itself is meaningful.



\---



\# 10. Z-Depth Explosion



Most cinematic default.



Pattern:



FLAT UI



→ layers separate toward/away from camera



→ relationships become visible



Useful for:



\- dashboards

\- AI products

\- system architecture



Maintain alignment.



\---



\# 11. Horizontal Explosion



Groups separate left/right.



Useful for:



\- feature categories

\- comparisons

\- workflow stages



Works well when product already has column-based structure.



\---



\# 12. Vertical Explosion



Layers separate upward/downward.



Useful for:



\- hierarchy

\- stack

\- infrastructure

\- layered architecture



Can visually communicate:



USER

↓

PRODUCT

↓

AUTOMATION

↓

DATA



\---



\# 13. Radial Explosion



Components move outward from a center.



Useful for:



\- ecosystem

\- integration hub

\- central AI

\- platform core



Use only when center genuinely represents the system hub.



\---



\# 14. Functional Cluster Explosion



Groups move according to function.



Example:



SALES

↖



MARKETING

↑



SUPPORT

↗



CORE PRODUCT

center



Useful for platform breadth.



Keep cluster relationships obvious.



\---



\# 15. Explosion Origin



Define where separation originates.



Possible:



CENTER



HERO FEATURE



CLICK POINT



AI CORE



DATA NODE



LOGO



The origin should have narrative meaning.



\---



\# 16. Explosion Trigger



Possible triggers:



CLICK



CAMERA LANDING



MUSICAL IMPACT



DATA ARRIVAL



AI ACTIVATION



VOICEOVER CUE



PRODUCT ACTION



Do not explode interface without a trigger.



\---



\# 17. Pre-Explosion State



Show enough of the complete product first.



Pattern:



COMPLETE UI

→ HOLD

→ TRIGGER

→ EXPLOSION



If viewer never understands the original product,

the separated state loses meaning.



\---



\# 18. Separation Phase



During separation:



preserve recognizable relationships.



Useful controls:



\- distance

\- delay

\- easing

\- depth

\- rotation

\- opacity



Scale should usually remain relatively stable.



\---



\# 19. Explosion Hierarchy



Not every layer travels the same distance.



Possible:



HERO

largest emphasis



PRIMARY SUPPORT

medium



CONTEXT

small



AMBIENT

minimal



Distance can encode importance.



\---



\# 20. Depth Hierarchy



Example conceptual layout:



FOREGROUND

hero feature



MID-FRONT

primary controls



CENTER

main product plane



MID-BACK

support/data



BACKGROUND

system/environment



Exact depth depends on shot.



\---



\# 21. Rotation



Use rotation to reinforce dimensionality.



Keep subtle for readable UI.



Possible:



X tilt



Y tilt



small Z rotation



Avoid random rotations for every component.



\---



\# 22. Scale



Depth already communicates distance.



Avoid combining large:



TRANSLATION

\+

ROTATION

\+

SCALE



on every element.



One dominant spatial mechanism is usually stronger.



\---



\# 23. Opacity



Opacity can help reduce non-hero layers.



Do not make separated architecture disappear unnecessarily.



The purpose is to understand relationships.



\---



\# 24. Camera



Strong options:



STATIC CAMERA

→ interface separates around viewer



SLOW PUSH

→ camera enters architecture



SLOW PULL

→ reveal increasing complexity



ORBIT

→ inspect dimensional structure



FOLLOW

→ follow one component through system



\---



\# 25. Static Camera Explosion



Useful when explosion itself is the hero.



Benefits:



\- easy to understand

\- strong silhouette

\- less competing motion



Good default.



\---



\# 26. Push Into Explosion



Pattern:



PRODUCT

→ EXPLODES

→ CAMERA PUSHES BETWEEN LAYERS



Useful for transitioning into:



\- architecture

\- feature

\- data flow



\---



\# 27. Pull-Out Explosion



Pattern:



FEATURE

→ CAMERA PULLS

→ MORE LAYERS APPEAR

→ COMPLETE SYSTEM REVEALED



Useful for ecosystem payoff.



\---



\# 28. Orbit Inspection



Camera moves slightly around separated structure.



Useful for:



\- hero architecture

\- premium product film



Avoid full unnecessary 360° rotation.



Small angular change is often enough.



\---



\# 29. Camera Through Layers



Camera passes through separated components.



Useful for:



\- feature transitions

\- architecture navigation

\- product world-building



Each layer passed should lead logically to next information.



\---



\# 30. Composition



Before separation,

design both:



ASSEMBLED FRAME



and



EXPLODED FRAME.



Both must work visually.



Do not assume the exploded state will compose itself automatically.



\---



\# 31. Exploded Composition



Check:



\- silhouette

\- negative space

\- overlap

\- hero visibility

\- perspective

\- safe areas

\- depth readability



Avoid layers becoming visually tangled.



\---



\# 32. Layer Spacing



Spacing should communicate structure.



Too little:



layers remain visually merged.



Too much:



relationship between components is lost.



Find the minimum separation required to reveal architecture.



\---



\# 33. Alignment



Exploded View should often preserve alignment guides.



Example:



cards remain aligned along original columns.



This makes origin obvious.



\---



\# 34. Connection Lines



Use when relationships would otherwise be unclear.



Possible:



\- lines

\- paths

\- beams

\- pulses



Do not connect everything.



Highlight only meaningful relationships.



\---



\# 35. Labels



For explanatory decomposition,

labels may identify groups.



Example:



DATA



AUTOMATION



AI



INTEGRATIONS



Keep labels secondary to visual structure.



\---



\# 36. Lighting



Depth can be reinforced with:



\- edge light

\- hero illumination

\- atmospheric falloff

\- environmental spill



Do not glow every layer.



\---



\# 37. Shadows



Separated layers may gain stronger spatial shadows.



As they reassemble:



shadows should return toward original product state.



\---



\# 38. Depth of Field



Can reinforce distance.



But important layers must remain readable.



Use DOF more aggressively only during cinematic inspection,

not information-heavy explanation.



\---



\# 39. Parallax



Camera movement + separated layers naturally creates parallax.



Do not add independent drifting motion unnecessarily.



\---



\# 40. Ambient Motion



Possible:



\- subtle float

\- light drift

\- slow data pulses

\- restrained environmental movement



Explosion itself should remain primary.



\---



\# 41. Sound Structure



Useful sequence:



PRE-TRIGGER

subtle tension



TRIGGER

impact



SEPARATION

layered whoosh



LANDING

low/tactile settle



DETAIL

small digital cues



REASSEMBLY

reverse/converging motion



Avoid one loud whoosh per layer.

\---



\# 64. Avoid Fake Architecture



Never create:



AI LAYER

DATABASE

API

AUTOMATION



unless these concepts are supported by actual product or explicitly

presented as conceptual abstraction.



Visual sophistication must not misrepresent functionality.



\---



\# 65. Avoid Random Cards



Bad:



every card flies in a different direction.



Better:



groups separate according to functional or spatial logic.



\---



\# 66. Avoid Excessive Rotation



Readable UI should not become a deck of spinning cards.



Use rotation to communicate depth,

not spectacle.



\---



\# 67. Avoid Infinite Separation



Components should remain visually related.



If viewer cannot reconstruct original product mentally,

separation is too large.



\---



\# 68. Avoid Simultaneous Maximum Motion



Do not combine:



EXPLOSION

\+

FAST CAMERA

\+

ROTATION

\+

PARTICLES

\+

TEXT

\+

CURSOR



Choose hierarchy.



\---



\# 69. Avoid No Hold



Exploded state needs enough time to be understood.



Pattern:



SEPARATE

→ SETTLE

→ READ

→ CONTINUE



\---



\# 70. Avoid Meaningless Reassembly



Do not reassemble merely because effect must reverse.



Reassembly should serve:



\- product return

\- transition

\- payoff

\- brand resolve



\---



\# 71. Timing Structure



Useful conceptual timing:



PREPARE

10–15%



SEPARATE

20–30%



SETTLE

10%



INSPECT / EXPLAIN

25–40%



TRANSITION / REASSEMBLE

15–25%



Adjust based on complexity.



\---



\# 72. Explosion Timing



Layers may separate with controlled stagger.



Possible order:



HERO

→ PRIMARY

→ SECONDARY

→ SYSTEM



or reverse.



Choose based on story.



\---



\# 73. Separation Easing



Prefer controlled easing.



Premium explosion usually feels better with:



fast initial separation

→ smooth deceleration



Avoid playful bounce unless brand supports it.



\---



\# 74. Reassembly Easing



Reassembly may feel slightly more decisive.



Pattern:



layers accelerate toward origin

→ settle precisely



Avoid uncontrolled overshoot on serious products.



\---



\# 75. Motion Hierarchy



Primary:



LAYER SEPARATION



Secondary:



CAMERA / LIGHT



Ambient:



ENVIRONMENT



Do not create multiple primary motions.

\# 86. Implementation Routing



Use REMOTION when:



\- UI is code-based

\- product data drives scene

\- reusable variants are needed

\- programmatic timing matters



Use AFTER EFFECTS when:



\- detailed compositing

\- advanced 2.5D

\- manual art direction

\- complex visual polish



Use DAVINCI/FUSION when:



\- integrated editorial/compositing

\- final finishing

\- existing DaVinci workflow

\# 90. Creative Director Rule



Never request:



"explode all the cards."



Define:



WHAT STRUCTURE IS BEING REVEALED?



Example:



The dashboard separates into three functional planes:



FRONT:

AI recommendation card



CENTER:

customer analytics dashboard



BACK:

data and automation layer



The camera makes a small lateral move after separation,

creating parallax that clarifies the relationship.



The AI card remains brightest because it is the narrative hero.



After the explanation,

the camera follows the AI layer into the next feature shot.



Now the explosion communicates architecture instead of decoration.



\---



\# 91. Golden Rule



Separation must reveal meaning.



If the viewer learns nothing from seeing the interface separated,

do not explode it.



Structure first.



Space second.



Camera third.



Effects last.
