# Feature Launch

## Role

Specialization for introducing one primary feature or capability.

Load after:

workflows/product-video-master.md

---

# Feature Principle

The feature name is rarely the story.

The story is:

WHAT CHANGES FOR THE USER?

Translate:

FEATURE
-> BEHAVIOR
-> BENEFIT
-> PROOF

---

# Scope Discipline

A feature launch should protect the hero capability.

Avoid turning it into a full product overview.

Supporting features may appear only when they explain or strengthen the hero.

---

# Narrative Options

## Problem -> Feature -> Result

Useful when pain creates context.

## Old Way -> New Way

Useful for workflow improvements.

## Reveal -> Demonstration -> Proof

Useful for major capabilities.

## Input -> Intelligence -> Output

Useful for AI, automation or transformation features.

Do not imply invisible intelligence unless supported by product evidence.

---

# Demonstration

Show the feature doing the thing that makes it valuable.

Avoid:

FEATURE NAME
-> DECORATIVE ANIMATION
-> CTA

when actual product behavior can be demonstrated.

---

# Before / After

When using comparison, keep variables controlled.

The viewer must understand exactly what changed.

Do not exaggerate the old state to manufacture improvement.

---

# Feature Copy

Prefer benefit-led copy when appropriate.

But do not hide the actual function behind vague marketing language.

The viewer should leave knowing:

WHAT IT IS

and:

WHY IT MATTERS.

---

# Feature Quality Gate

Before finalizing, ask:

IS ONE FEATURE CLEARLY THE HERO?

IS ITS BEHAVIOR UNDERSTANDABLE?

IS ITS VALUE UNDERSTANDABLE?

DID WE PROVE THE CLAIM VISUALLY?

DID SECONDARY INFORMATION DILUTE THE HERO?

If so, remove or demote secondary material.
