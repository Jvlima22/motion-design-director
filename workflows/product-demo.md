# Product Demo

## Role

Specialization for demonstrating how a product completes a task or workflow.

Load after:

workflows/product-video-master.md

---

# Demo Principle

A demo is a causal story.

USER INTENT
-> ACTION
-> PRODUCT RESPONSE
-> RESULT

The viewer should understand what caused what.

---

# Define the Task

Before planning shots, write:

USER GOAL:
STARTING STATE:
REQUIRED ACTIONS:
PRODUCT RESPONSES:
END STATE:
VALUE OF RESULT:

Remove steps that do not contribute to understanding.

---

# Interaction Fidelity

Product interaction is evidence.

Preserve:

- meaningful states
- actual labels
- actual controls
- causal order
- important feedback
- result

Do not change the workflow merely to make animation easier.

---

# Cursor and Gesture

Cursor or touch indicators should clarify causality.

Use them when the viewer needs to understand:

WHAT WAS SELECTED?

WHAT CAUSED THE CHANGE?

WHERE DID THE ACTION OCCUR?

Do not animate a cursor continuously merely to simulate activity.

---

# Temporal Compression

Real workflows may contain waiting, typing or navigation that is too slow for film.

Compress time without breaking causal understanding.

Possible methods:

- cut
- match cut
- accelerated typing
- controlled time compression
- state transition
- camera reframing
- progressive reveal

Never remove a causal step if doing so makes the product appear magical.

---

# Focus

At every moment identify:

ACTION TARGET

and:

RESULT TARGET

Use composition and motion to direct attention between them.

---

# Copy

Demo copy should support interaction rather than compete with it.

Prefer visual proof when the interface already communicates the message.

---

# Demo Quality Gate

Before finalizing, ask:

CAN THE VIEWER IDENTIFY THE USER GOAL?

CAN THEY FOLLOW THE CAUSAL CHAIN?

ARE IMPORTANT INTERACTIONS REAL?

IS ANY NECESSARY STEP MISSING?

IS THE RESULT CLEAR?

COULD ANY SHOT BE REMOVED WITHOUT LOSING UNDERSTANDING?

If yes, consider removing it.
