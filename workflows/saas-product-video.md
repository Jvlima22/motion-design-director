# SaaS Product Video

## Role

Specialization for SaaS and software product films.

Load after:

workflows/product-video-master.md

This file modifies the Master Workflow.
It does not replace it.

---

# Primary Communication Problems

SaaS videos commonly need to make an abstract software product:

- understandable
- tangible
- differentiated
- trustworthy
- desirable

The interface is evidence, not automatically the story.

---

# Product Truth Emphasis

Verify:

- actual screens
- actual workflows
- integrations
- automation behavior
- AI behavior
- analytics
- metrics
- collaboration behavior
- permissions
- outputs

Do not invent SaaS capabilities merely because they are visually plausible.

---

# Value Before Interface

Determine:

WHAT BUSINESS OR USER PROBLEM CHANGES?

Then:

WHAT PRODUCT BEHAVIOR CAUSES THAT CHANGE?

Then:

WHAT UI EVIDENCE PROVES IT?

Prefer:

VALUE
-> BEHAVIOR
-> EVIDENCE

over:

SCREEN
-> SCREEN
-> SCREEN

---

# Recommended Narrative Strategies

Strong defaults include:

PROBLEM
-> PRODUCT
-> WORKFLOW
-> OUTCOME

or:

PROMISE
-> CAPABILITY
-> PROOF
-> RESULT

or:

PRODUCT REVEAL
-> KEY WORKFLOWS
-> DIFFERENTIATION
-> RESOLUTION

Choose according to the communication goal.

---

# UI Treatment

Do not show the entire interface merely because it exists.

Use:

- crop
- focus
- zoom
- cursor
- state change
- progressive disclosure
- feature isolation
- data flow
- contextual callout

when they improve comprehension.

Preserve enough real UI context that the viewer understands what is being shown.

---

# Trust

SaaS credibility is damaged by:

- fake dashboards
- impossible metrics
- meaningless charts
- fabricated customer results
- fake integrations
- AI magic without product evidence

When proof matters, make proof visually legible.

---

# Density

Enterprise or technical SaaS may naturally contain dense interfaces.

Do not solve density by reproducing the whole dashboard at unreadable scale.

Select the evidence required for the current message.

---

# Ending

Possible endings include:

- product identity
- core promise
- result
- CTA
- availability
- URL
- brand resolution

CTA is not mandatory unless the communication goal requires conversion.

# SaaS Quality Gate

Before finalizing, ask:

CAN THE VIEWER EXPLAIN WHAT THE PRODUCT DOES?

CAN THEY EXPLAIN WHY IT MATTERS?

DID WE SHOW PRODUCT EVIDENCE?

ARE ALL IMPORTANT CLAIMS SUPPORTED?

IS THE UI LEGIBLE WHEN IT NEEDS TO BE?

If not, simplify the communication before adding polish.
