\# SFX LANGUAGE



SFX language is the vocabulary used to translate visual events into intentional sound choices.



The purpose of this module is not to decide whether a scene needs sound.



That belongs primarily to:



```text

references/audio/sound-design.md

```



The purpose here is to answer:



```text

WHAT KIND OF SOUND

BEST EXPRESSES

THIS VISUAL EVENT?

```



\---



\# CORE PRINCIPLE



Do not search for:



```text

"a cool sound effect"

```



Search for:



```text

THE SONIC BEHAVIOR

OF THE VISUAL EVENT

```



A useful SFX decision considers:



```text

EVENT

→ FUNCTION

→ MOTION

→ SCALE

→ MATERIAL

→ ENERGY

→ TEXTURE

→ ATTACK

→ BODY

→ TAIL

→ VARIATION

```



\---



\# SFX LANGUAGE DECISION CHAIN



```text

WHAT HAPPENS VISUALLY?

&#x20;       ↓

WHAT DOES THE EVENT COMMUNICATE?

&#x20;       ↓

WHAT PHYSICAL OR DIGITAL BEHAVIOR DOES IT SUGGEST?

&#x20;       ↓

WHAT IS ITS SCALE?

&#x20;       ↓

WHAT MATERIAL DOES IT FEEL LIKE?

&#x20;       ↓

HOW FAST IS THE MOTION?

&#x20;       ↓

HOW IMPORTANT IS THE EVENT?

&#x20;       ↓

WHAT ATTACK SHOULD IT HAVE?

&#x20;       ↓

WHAT BODY SHOULD IT HAVE?

&#x20;       ↓

WHAT TAIL SHOULD IT HAVE?

&#x20;       ↓

WHICH SFX FAMILY MATCHES?

&#x20;       ↓

DOES IT NEED LAYERING?

&#x20;       ↓

DOES IT FIT THE PRODUCT'S SONIC LANGUAGE?

```



\---



\# 1. SFX IS A LANGUAGE



Sound effects should behave like a vocabulary.



A consistent product video may develop recurring sonic words for:



```text

movement

selection

confirmation

arrival

transition

activation

success

data

connection

brand

```



The viewer may not consciously identify those patterns.



But consistency creates cohesion.



\---



\# 2. FUNCTION BEFORE FILE NAME



Never choose an effect merely because the filename says:



```text

whoosh\_07.wav

impact\_big.wav

tech\_click.wav

```



Ask what the sound needs to do.



Examples:



```text

MOVE

LAND

CONFIRM

OPEN

CLOSE

CONNECT

BUILD

REVEAL

TRANSFORM

COMPLETE

```



Then choose the appropriate family.



\---



\# 3. PRIMARY SFX FAMILIES



Core families include:



```text

WHOOSH

IMPACT

RISER

SPARKLE

CLICK

POP

SNAP

TRANSITION

MECHANICAL

DIGITAL

FOLEY

AMBIENCE

TEXTURE

```



These are functional categories.



They may be combined.



\---



\# 4. WHOOSH



Use a whoosh when sound should communicate:



```text

movement through space

fast translation

camera travel

object travel

transition momentum

```



Common relationships:



```text

CAMERA MOVE

→ whoosh



CARD FLY-IN

→ light whoosh



DEVICE SWEEP

→ medium whoosh



FAST SCENE TRANSITION

→ stronger whoosh

```



\---



\# 5. WHOOSH CHARACTER



Whooshes can feel:



```text

soft

airy

clean

sharp

heavy

cinematic

digital

organic

metallic

futuristic

```



Choose based on art direction.



Do not use the same generic cinematic whoosh for every movement.



\---



\# 6. WHOOSH SCALE



Match perceived sound scale to visual scale.



```text

tiny UI chip

→ micro air movement



card

→ light whoosh



large panel

→ medium whoosh



full composition

→ broad whoosh



camera crossing environment

→ large spatial whoosh

```



The sound should not imply an object much larger than the visual event unless exaggeration is intentional.



\---



\# 7. WHOOSH TIMING



For movement:



```text

ONSET

→ movement begins



PEAK

→ maximum perceived velocity



TAIL

→ movement resolves

```



The strongest part of the whoosh often belongs near maximum motion rather than automatically at the first frame.



Use:



```text

references/audio/audio-motion-sync.md

```



for precise audiovisual alignment.



\---



\# 8. IMPACT



Use an impact when something:



```text

lands

arrives

locks

hits

resolves

becomes dominant

```



Examples:



```text

hero dashboard lands

metric locks

device arrives

logo resolves

major panel snaps into place

```



\---



\# 9. IMPACT SCALE



Possible hierarchy:



```text

MICRO IMPACT

UI confirmation



SMALL IMPACT

card landing



MEDIUM IMPACT

feature reveal



LARGE IMPACT

hero product



HERO IMPACT

climax / brand moment

```



Do not give every event hero-scale impact.



\---



\# 10. IMPACT ANATOMY



An impact may contain:



```text

ATTACK

BODY

TAIL

```



\## ATTACK



Defines immediacy.



Examples:



```text

click

snap

crack

transient

```



\## BODY



Defines weight.



Examples:



```text

thump

slam

low-frequency hit

mechanical body

```



\## TAIL



Defines space and aftermath.



Examples:



```text

reverb

ring

air

sparkle

decay

```



A sophisticated impact may layer all three.



\---



\# 11. RISER



A riser communicates:



```text

anticipation

build

approach

increasing energy

transition toward a target

```



Use before:



```text

hero reveal

drop

major transition

feature climax

brand reveal

```



A riser should lead somewhere.



Do not create buildup without payoff.



\---



\# 12. RISER DIRECTION



Typical:



```text

LOW ENERGY

→ INCREASING ENERGY

→ TARGET

```



The target may be:



```text

impact

cut

drop

reveal

silence

```



A riser ending without a meaningful visual event weakens the phrase.



\---



\# 13. SPARKLE



Sparkles communicate:



```text

polish

completion

highlight

magic

premium detail

successful resolution

```



Good uses:



```text

logo finishing

successful action

small glow

hero detail

polished UI state

```



Use sparingly.



Too many sparkles can make professional SaaS motion feel decorative or childish.



\---



\# 14. CLICK



Clicks communicate:



```text

input

selection

activation

press

confirmation

```



Common events:



```text

button

toggle

tab

cursor click

selection

```



A click should normally relate to the actual pressed or activated state.



Not merely cursor proximity.



\---



\# 15. DIGITAL CLICK



A digital click may be:



```text

clean

short

precise

high-frequency

minimal

```



Useful for:



```text

SaaS

dashboard

productivity software

AI tools

developer tools

```



Avoid excessive click sounds for every micro-interaction.



\---



\# 16. MECHANICAL CLICK



Mechanical clicks suggest:



```text

physicality

switches

hardware

precision

tactility

```



Useful when visual design suggests:



```text

switch

dial

mechanism

device

control surface

```



Do not use physical mechanical sounds for purely digital interfaces without stylistic reason.



\---



\# 17. POP



A pop communicates:



```text

appearance

small expansion

light confirmation

playful activation

```



Good for:



```text

badge

bubble

small card

notification

avatar

chip

```



Use carefully in premium or serious enterprise products.



\---



\# 18. SNAP



A snap communicates:



```text

precision

fast locking

decisive alignment

sharp transition

```



Good for:



```text

panel lock

grid alignment

feature replacement

layout transformation

```



A snap is often more precise than a heavy impact.



\---



\# 19. TRANSITION SFX



Transition sounds communicate movement between states or scenes.



Possible families:



```text

whoosh

sweep

reverse

suction

pass-by

tonal transition

noise sweep

digital transition

```



Choose according to transition geometry.



\---



\# 20. TRANSITION GEOMETRY



Match sound to visual behavior.



```text

horizontal wipe

→ directional sweep



zoom

→ spatial acceleration



push transition

→ movement whoosh



collapse

→ suction / contraction



expansion

→ bloom / outward movement



digital replacement

→ synthetic transition

```



The sound should reinforce what the eye perceives.



\---



\# 21. DIRECTIONAL SOUND



Movement direction can influence sound design.



Examples:



```text

LEFT → RIGHT

RIGHT → LEFT

UP

DOWN

TOWARD CAMERA

AWAY FROM CAMERA

```



Do not exaggerate stereo movement unnecessarily.



But spatial behavior can reinforce large cinematic transitions.



\---



\# 22. FOLEY



Foley represents physical interaction.



Examples:



```text

touch

cloth

paper

desk

device

keyboard

hand movement

mechanical control

```



Foley can make abstract motion feel grounded.



Use it when physical realism helps.



\---



\# 23. DIGITAL SFX



Digital sounds suggest:



```text

software

data

computation

connection

system state

processing

AI

```



Possible qualities:



```text

clean

synthetic

tonal

glitchy

granular

precise

minimal

```



Avoid generic sci-fi sounds unless the product's art direction supports them.



\---



\# 24. DATA SOUNDS



Data movement can use:



```text

ticks

pulses

small digital transients

tonal sequences

connection cues

```



For:



```text

charts

nodes

integrations

automation

data transfer

metrics

```



Do not sonify every data point.



Sound important state changes.



\---



\# 25. CONNECTION SOUNDS



For:



```text

node connection

API connection

integration

automation link

data routing

```



consider:



```text

source activation

→ movement cue

→ destination confirmation

```



This creates a sonic path.



\---



\# 26. AI / PROCESSING SOUNDS



AI processing does not require stereotypical:



```text

robot noises

random glitch

sci-fi beeps

```



Instead consider:



```text

soft pulses

layered digital texture

tonal movement

controlled granular detail

subtle processing rhythm

```



The sound should match the product's brand.



\---



\# 27. NOTIFICATION SOUNDS



Notifications should be:



```text

short

recognizable

non-fatiguing

hierarchical

```



Differentiate:



```text

INFO

SUCCESS

WARNING

ERROR

```



without creating unnecessary alarm.



\---



\# 28. SUCCESS SOUNDS



Success can be represented with:



```text

positive tonal movement

light sparkle

small confirmation impact

ascending cue

```



Scale to importance.



A saved setting should not sound like winning a championship.



\---



\# 29. ERROR SOUNDS



Errors can use:



```text

short negative tone

low movement

controlled dissonance

dry rejection cue

```



Avoid unnecessarily harsh alarm sounds in normal UI demonstrations.

\# 32. METAL

\# 33. AIR

\# 35. PHYSICAL + DESIGNED HYBRID



A strong product sound may combine:



```text

PHYSICAL FOUNDATION

\+

DESIGNED DETAIL

```



Example:



```text

\+

soft digital tone

```



Or:



```text

=

physical impact

\+

\+

```



This can create believable but branded sonic behavior.

\# 37. MICRO SFX


\# 38. HERO SFX

```text

multiple layers

```

\---



\# 39. ATTACK



Attack describes how quickly a sound establishes itself.



\## FAST ATTACK



Useful for:



```text

click

snap

impact

selection

```



\## SOFT ATTACK



Useful for:



```text

ambient reveal

slow movement

glow

fade

```



Match visual acceleration.



\---



\# 40. BODY



The body gives a sound perceived substance.



Possible body:



```text

low thump

mid punch

mechanical weight

tonal core

noise body

```



More body generally implies greater perceived scale.



\---



\# 41. TAIL



Tail is what happens after the primary event.



Possible tails:



```text

reverb

delay

ring

sparkle

air

noise decay

tonal decay

```



Tail helps communicate:



```text

space

scale

polish

continuity

```



Do not hard-cut useful tails without reason.



\---



\# 42. REVERB



Reverb can communicate environment and scale.



Use carefully.



Too much reverb can:



```text

blur timing

muddy UI

reduce precision

mask music

```



Modern product videos often benefit from controlled tails rather than huge cinematic reverbs everywhere.

\# 43. DRY VS WET



\## DRY



Feels:



```text

close

precise

technical

immediate

```



\## WET



Feels:



```text

spacious

cinematic

large

atmospheric

```



Match art direction and shot scale.



\---



\# 44. TONAL VS ATONAL



\## TONAL



Contains recognizable pitch.



Useful for:



```text

brand

success

premium UI

notifications

```



\## ATONAL



Focuses on:



```text

noise

texture

physical transient

movement

```



Useful for:



```text

whooshes

impacts

transitions

foley

```



Combining both can produce richer results.



\---



\# 45. LOW / MID / HIGH FREQUENCY LANGUAGE



\## LOW



Communicates:



```text

weight

scale

power

```



\## MID



Communicates:



```text

body

presence

mechanical detail

```



\## HIGH



Communicates:



```text

precision

sparkle

click

```



Layer according to event function.



\---



\# 46. LAYERING



Do not layer sounds simply to make them louder.



Layer when each sound contributes a different function.



Example:



```text

HERO IMPACT



LAYER 1

attack



LAYER 2

weight



LAYER 3

tonal identity



LAYER 4

tail

```



Every layer should justify itself.



\---



\# 47. COMPLEMENTARY LAYERS



Strong layers occupy different roles.



Avoid:



```text

three nearly identical impacts

```



Prefer:



```text

sharp transient

\+

low body

\+

textural tail

```



\---



\# 48. SFX PHRASES



Effects can form phrases.



Example:



```text

RISER

→ IMPACT

→ SPARKLE

```



Meaning:



```text

anticipation

→ event

→ aftertaste

```



Other phrase:



```text

CLICK

→ PROCESS

→ SUCCESS

```



Or:



```text

ACTIVATION

→ DATA MOVEMENT

→ DESTINATION CONFIRMATION

```



Think in sonic sentences.



\---



\# 49. VARIATION



Repeated visual events should not necessarily use the identical sample.



Use:



```text

variant A

variant B

variant C

```



with similar sonic identity.



Variation prevents machine-gun repetition.



\---



\# 50. CONSISTENCY



Variation must not destroy vocabulary.



Good:



```text

three related click variants

```



Bad:



```text

mechanical click

cartoon pop

laser

wood knock

```



for four identical buttons.



\---



\# 51. REPEATED SERIES



For repeated items:



```text

card 1

card 2

card 3

card 4

```



consider:



```text

rhythmic spacing

sample variation

pitch variation

intensity progression

selective omission

```



The sequence should sound intentional.



\---



\# 52. SELECTIVE OMISSION



Sometimes the best SFX choice is:



```text

NO SOUND

```



Do not sound:



```text

every hover

every tiny text change

every decorative particle

every minor UI movement

```



Silence preserves hierarchy.



\---



\# 53. DENSITY



SFX density should reflect scene importance.



Possible model:



```text

LOW

ambient + major events



MEDIUM

major + selected secondary events



HIGH

rhythmic sequence / climax

```



Return to lower density after high-density sections.



Contrast creates impact.

\# 63. UI EXPLOSION

```text

selected object accents

```



Do not assign a loud whoosh to every fragment.



\---



\# 64. FLOATING UI


\---



\# 65. DATA FLOW


\# 66. CURSOR

\---



\# 71. SAMPLE PEAK



A sample's perceptual peak may occur after its file begins.



Therefore:



```text

FILE START

≠

PERCEPTUAL EVENT

```



Align the relevant transient or peak to the intended visual event.



Do not align blindly by clip start.



\---



\# 72. TRIM



Trim unnecessary silence or pre-roll when appropriate.



But do not destroy:



```text

natural attack

useful anticipation

reverb tail

```



Understand the sample before trimming.

\# 76. REMOTION IMPLEMENTATION



Represent SFX semantically.



Prefer:



```tsx

const SFX = {

&#x20; heroImpact: "...",

&#x20; uiClick: "...",

&#x20; transitionSoft: "...",

&#x20; success: "...",

};

```



over scattered anonymous files.



Then use event registries.



Concept:



```tsx

const EVENTS = \[

&#x20; {

&#x20;   frame: HERO\_LAND,

&#x20;   sound: SFX.heroImpact,

&#x20; },

];

```



This preserves intent.

\---



\# 80. ANTI-PATTERNS



Avoid:



```text

SOUNDING EVERY MOVEMENT



USING THE SAME WHOOSH EVERYWHERE



USING THE SAME IMPACT AT EVERY SCALE



USING HERO IMPACTS FOR MICRO UI



USING CARTOON POPS IN SERIOUS ENTERPRISE MOTION WITHOUT INTENT



USING GENERIC SCI-FI FOR EVERY AI PRODUCT



ADDING GLITCH BECAUSE THE PRODUCT IS "TECH"



STACKING LAYERS THAT SERVE THE SAME FUNCTION



CUTTING EVERY REVERB TAIL



USING RANDOM MATERIAL LANGUAGES



USING RANDOM CLICK TYPES FOR IDENTICAL ACTIONS



USING SOUND ONLY BECAUSE AN ASSET EXISTS



TRUSTING FILE NAMES WITHOUT AUDITIONING



ALIGNING FILE START INSTEAD OF THE PERCEPTUAL TRANSIENT



USING LOUDNESS TO CREATE IMPORTANCE INSTEAD OF HIERARCHY



FILLING EVERY SILENT SPACE

```

\---



\# 82. PRODUCT TRUTH



SFX should reinforce what the product actually does.



Do not use sound to imply:



```text

a successful action that never happened

a connection that was never established

a notification that does not exist

a completion state the UI does not show

```



Stylization is allowed.



Misrepresentation is not.

\# GOLDEN RULE



Sound the behavior, not the object name.



Choose SFX by function.



Match scale.



Match material.



Match motion.



Match art direction.



Build consistent sonic vocabulary.



Use variation without losing identity.



Reserve large sounds for large moments.



Leave unimportant events silent.



And audition every effect against the actual picture and music.
